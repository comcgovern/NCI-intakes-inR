# Code audit: nciusual v0.4.1 vs the NCI SAS macros (October 2026)

## How this audit was done

1. **Line-by-line review** of everything in `R/`, the tests, `PACKAGE_SPEC.md` and `README.md`.
2. **Comparison against the actual NCI v2.1 SAS source.** NCI publishes these at
   <https://epi.grants.cancer.gov/diet/usualintakes/macros_single.html>:
   `mixtran_macro_v2.1.sas` (10/04/2012), `distrib_macro_v2.1.sas` (10/04/2012) and
   `indivint_macro_v2.1.sas` (9/4/2012). The README cites "MIXTRAN v2.21 / DISTRIB v2.2".
   v2.1 is the version the NCI page links to; I could not find a v2.21 source to compare against.
3. **Numerical parity against NCI's published Example 1.** This is SAS `.lst` output on NCI's
   own analytic dataset (`indiv_ims.sas7bdat`): added sugars, males 9+, an amount-only model,
   `replicate_var=rndw1`, `seq=day2`, `weekend`, and `wkend_prop=3/7` in DISTRIB.
   The script is `data-raw/sas_parity_examples.R`. It downloads the data and prints every
   number below.
4. **Targeted R checks** of each suspected defect, on R 4.3.3, nlme 3.1-164 and lme4 1.1-35.1.

The existing test suite passes: 266 passed, 0 failed. That does not contradict the findings.
The "parity" fixtures in `data-raw/generate_reference.R` (lines 77–78, 109–110, 141–142) define
"true" usual intake as `boxcox_inverse(Xβ + u)`. That is the same definition the package uses,
so those tests compare the package with itself rather than with NCI's definition (see C1).

## Headline result

Using **SAS's own published parameter estimates** for Example 1:

| Overall statistic | SAS `.lst` | DISTRIB re-implemented from the SAS source | `nciusual` DISTRIB logic |
|---|---|---|---|
| Mean | 25.47 | 25.43 (−0.2%) | 22.73 (**−10.7%**) |
| P1 | 3.79 | 3.75 (−1.1%) | 2.21 (**−41.6%**) |
| P5 | 7.23 | 7.23 (+0.1%) | 5.32 (**−26.4%**) |
| P50 | 23.18 | 23.13 (−0.2%) | 20.43 (**−11.9%**) |
| P95 | 51.46 | 51.58 (+0.2%) | 48.16 (−6.4%) |
| % below 10 tsp | 10.5% | 10.5% | **16.2%** |

In the age subgroups, the package's P1 is 27–60% low. The SAS-faithful version matches SAS to
within Monte Carlo noise, typically under 1%. So the gap comes from the package's DISTRIB step
and not from simulation randomness.

The MIXTRAN step also differs. On NCI's data, `mixtran(..., weight_var = "rndw1")` **errors**.
Unweighted, it gives λ = 0.380 and σ²_u = 2.89, against SAS's 0.394 and 3.52.
A weighted-ML re-implementation of MIXTRAN reproduces SAS: λ = 0.3939, σ²_u = 3.513,
σ²_e = 4.071, and all fixed effects within about 0.02.

## Critical — results differ materially from SAS

### C1. DISTRIB omits the within-person back-transformation
`R/distrib.R:243-246` and `:293-297` compute usual intake as `T⁻¹(Xβ + u)`.
DISTRIB v2.1 (macro `MC`) integrates the back-transform over the within-person error instead:

```sas
/* back-transform A (amount on consumption day) to original scale */
/* 9 point approximation  */
if (a_lambda = 0) then do;
  predcda = exp(mc_bca&wk + a_var_e&ve / 2);
...
  do j=1 to 9;
     xbt[j]=mc_bca&wk + cj[j]*sqrt(a_var_e&ve);
     fbt[j]=(max(0,xbt[j]*a_lambda+1))**(1/a_lambda);
```

`T⁻¹(Xβ+u)` is the *median* day's intake, not the *expected* day's intake. That biases every
statistic downward, and the lower tail the most. `sigma2_w`/`sigma2_e` are already passed to
`simulate_amount_model()` but never used. `PACKAGE_SPEC.md` §2.4 ("Within-person error ε is
NOT drawn") is correct that ε is not drawn, but it misses that SAS integrates over ε.
This is the single largest source of the gap above. Adding only the 9-point step moves the
overall mean from 22.73 to 25.04.

### C2. Weekend handling: R uses weekday-only intake; SAS uses a 4/7 weekday + 3/7 weekend mix
`R/distrib.R:136-138` and `:147-161` set `weekend = 0`. In SAS, MIXTRAN writes `x1b1_0/x1b1_1`
and `x2b2_0/x2b2_1`, and DISTRIB combines them:

```sas
mc_t=((&wkday_prop*mc_t_0)+(&wkend_prop*mc_t_1));
```

The documented default is "4/7 and 3/7", and it can be changed with `wkend_prop`. The R package
has no `wkend_prop`. This accounts for most of the remaining gap after C1.

### C3. Survey weights are applied incorrectly in model fitting, and fail on real weights
`R/mixtran.R:510` and `:728` use `nlme::varFixed(~ 1/weight)`. That is per-observation
*precision* weighting, so it changes the residual-variance model; it does not weight the
likelihood. Consequences:

- The reported σ²_w scales linearly with the weights. In a simulation with true σ²_w = 0.64,
  the estimate is 0.644 unweighted, 1.255 with weights, and 2.511 with the same weights ×2.
- With NHANES-scale weights, `nlme` fails. Example 1 errors with raw `rndw1` and also with
  mean-normalised weights.
- It contradicts the package's own documentation. The README says weights are "used in
  DISTRIB, not likelihood", and the spec (§4.1, §6) calls for "unweighted model fitting".

MIXTRAN itself does something different from both. It weights each **subject's**
log-likelihood through the NLMIXED `REPLICATE` statement, and the weight must be integer-valued:

```sas
/*   "replicate_var"  Specifies the variable to be used in the replicate statement of PROC
                      NLMIXED or the freq statement of PROC UNIVARIATE.  The specified
                      variable must be integer valued.                                      */
```

The spec's statement that "NCI's approach is NOT pseudo-ML with weights" does not match the
v2.1 source. Matching SAS needs a subject-weighted likelihood, which `nlme`/`lme4` do not
provide. The audit's reference fit in `data-raw/sas_parity_examples.R` shows that a direct
closed-form weighted ML for the amount model reproduces SAS.

### C4. BRR full-sample estimate is unweighted while the replicates are weighted
In `R/brr.R:174`, `full_args` contains no `weight_var`. The `brr_usual_intake()` docs say
"Do not include weight_var here". Replicates set `args_k$weight_var <- ".brr_wt_"`
(`:202`). As a result:

- θ̂₀ is not survey-weighted.
- Each replicate deviation (θ̂_k − θ̂₀) includes the weighted-vs-unweighted difference, which
  inflates the SEs.
- Under C3, every replicate fit with real weights will error. Errors are caught as `NA`
  replicates (`:208-211`), so the result can silently be built from very few replicates.

### C5. Box-Cox λ is chosen differently from MIXTRAN
`R/mixtran.R:192-196` uses a grid search of the *marginal* positive amounts with **no
covariates** (`find_optimal_lambda(y_pos, lambda_grid = ...)`) and fixes λ. It then applies a
"λ < 0.15 → log" rule (`R/boxcox.R:101`). MIXTRAN v2.1 does three things differently:

- It gets a *starting* λ from `PROC TRANSREG ... BoxCox(... lambda=0.05 to 1 by 0.05) =
  identity(&vars_amt)`, a regression that includes the covariates, weekend and seq.
- It then **estimates λ jointly** in the NLMIXED mixed-model likelihood (`A_LAMBDA`,
  `bounds A_LAMBDA>0.01`).
- I found no 0.15→log rule in the v2.1 macro source.

In Example 1, R picks 0.380 and SAS 0.394. Separately, `find_optimal_lambda()` accepts
`covariates`, but `mixtran()` never passes them.

### C6. INDIVINT is a plug-in BLUP, not the SAS conditional expectation
INDIVINT v2.1 "performs adaptive Gaussian quadrature to predict usual intake for each
individual". It forms a numerator/denominator integral over the joint posterior of (u1, u2)
with a 6-point adaptive Gauss–Hermite rule (`indusint = intresn/intresd`). It also uses the
same 9-point ε back-transform, floored at `0.5*min_amt`. `R/indivint.R` instead returns
`T⁻¹(BLUP)` and `plogis(BLUP₁) × T⁻¹(BLUP₂)`, which drops three things:

- the posterior variance (Jensen bias);
- within-person variance (C1);
- ρ: never-consumers get v̂2 = 0 even in correlated models.

For regression calibration, this changes the calibration slope.

## Medium

- **M1. GHQ engine is not adaptive** (`R/mixtran.R:1116`). It uses fixed (prior-scaled) tensor
  nodes. `PACKAGE_SPEC.md` (v0.3) describes adaptive GHQ "matching SAS PROC NLMIXED", but
  `gh_nodes_adaptive()` is never called. Non-adaptive 5×5 nodes lose accuracy when σ²_e is
  small relative to σ²_v2.
- **M2. `gh_nodes_adaptive()` weights are incomplete** (`R/quadrature.R:471-473`). They lack the
  prior/standard-normal density ratio. Integrating 1 against the prior with no data gives
  0.954 instead of 1. The function is exported, though unused internally.
- **M3. The profile-ρ engine works on shrunken BLUPs** (`R/mixtran.R:956-968`). Never-consumers
  have r2 = 0, and the constrained unit-variance BVN likelihood biases ρ̂ (it tends to inflate
  it when shrinkage is heavy). This is documented as approximate. Treat it as an
  approximation, not SAS parity.
- **M4. `sequence` is always added** (`seq_num`, `R/mixtran.R:285`). SAS adds it only if the
  user passes `seq=`. This is a different default, not a bug.
- **M5. `vargroup` (separate residual variance by weekend) is not implemented.** DISTRIB can use
  it via `a_var_e_0/1`.
- **M6. `combine_nhanes_cycles()` divides weights by the number of cycles** (`R/brr.R:506`).
  That is correct only for cycles of equal length. The README example pools "2017-18, 2019-20,
  2021-22". 2017–March 2020 pre-pandemic (about 3.2 years) and August 2021–August 2023
  (2 years) need length-proportional weights. Verify against current CDC guidance, which may
  have changed since my knowledge cutoff.
- **M7. `skip_if_empty = FALSE` still returns NULL** in several paths
  (`prepare_mixtran_data()` returns NULL regardless), contradicting the docs.
- **M8. BRR robustness.** `theta_matrix - theta0` aligns by position, not name
  (`R/brr.R:237-242`). A replicate that loses a subgroup misaligns or recycles. `n_cores` is
  ignored when `future.apply` is installed.

## Low

- `.GH_TABLES$"7"`: the ±0.8162877718535 node is wrong in the 7th decimal place (correct value
  0.8162878828589647, error 1.1e-7).
- `get_subject_level_data()` is O(n_subjects × n_rows) via `lapply`/`==`. That is slow for
  NHANES × BRR (32+ replicates).
- `distrib()` / `distrib_bivariate()` call `set.seed()`, which changes the caller's global RNG
  state.
- `n_positive` / `pct_consuming` report 100% for amount models after zero replacement.
- `distrib_bivariate()` simulates the probability random effect v1 independently of v2 for
  two-part components, even when the component's own ρ ≠ 0 (`R/bivariate.R:265-271`). It also
  estimates cross-ρ from shrunken BLUPs.
- `Rplots.pdf` is committed at the repo root.

## Recommended fix order

1. **DISTRIB parity (C1, C2, H1, H6).** These are self-contained, and
   `data-raw/sas_parity_examples.R` already shows that the SAS logic reproduces the SAS output.
   The reference fixtures and parity tests must be regenerated with NCI's definition of usual
   intake (E over ε).
2. **Weights (C3, C4).** First decide between a subject-weighted likelihood (SAS parity) and
   the documented "unweighted fit" design. Either way, remove `varFixed`, and make the BRR
   full-sample run use the base weight.
3. **λ estimation (C5).** Estimate λ jointly in the likelihood, as NLMIXED does. For the amount
   model this is closed form and fast; see the reference fit in the parity script.
4. **INDIVINT (C6), H2–H5**, then the medium and low items.
5. Add Example 1 (and Example 2/4 for corr/INDIVINT) as a parity test with tolerances. NCI's
   dataset is about 14 MB, so it should be downloaded and the test skipped when offline.

## Resolution status (v0.5.0)

After the audit, the package was changed to do what the SAS macros do. The script that produced the "nciusual" columns above used the pre-0.5.0 code. `data-raw/sas_parity_examples.R` now runs the package itself on Examples 1 and 2.

| Item | Status in v0.5.0 |
|---|---|
| C1 back-transformation over ε | Fixed: DISTRIB 9-point rule / exact lognormal |
| C2 weekday/weekend averaging | Fixed: `wkend_prop`, default 3/7 |
| C3 weights in the likelihood | Fixed: subject-level REPLICATE weighting in a new ML engine |
| C4 BRR full-sample weight | Fixed: base weight; replicates warm-start |
| C5 λ estimation | Fixed: λ estimated in the likelihood; TRANSREG-style start; no 0.15 rule |
| C6 INDIVINT | Fixed: conditional expectation by adaptive quadrature |
| H1 never-consumer covariates | Fixed: predictors for every subject from their own covariates |
| H2 GHQ shift ignored by INDIVINT | Moot: single joint engine |
| H3 two-part `predicted_usual` | Fixed: now `indusint` |
| H4 factor subgroup | Fixed |
| H5 warm start | Fixed: `start` sets all starting values |
| H6 half-min floor | Fixed |
| M1/M2 adaptive GHQ | Fixed: engine uses adaptive quadrature; `gh_nodes_adaptive()` weights corrected |
| M3 profile-ρ | Removed (joint ML instead) |
| M4 `seq` default | Kept as an option (`include_seq = TRUE`) |
| M5 `vargroup` | Not implemented (documented gap) |
| M6 unequal cycle lengths | `cycle_years` added |
| M7 `skip_if_empty = FALSE` | Fixed: errors |
| M8 BRR alignment | Fixed: aligned by name |
| Low: GH 7-node, RNG side effect, `Rplots.pdf` | Fixed |
| Bivariate | Still an approximation (not a port of the NCI multivariate macros), now with DISTRIB's back-transformation |

Remaining known gaps: `vargroup`, DISTRIB's per-person `recamt` comparison, and the NCI multivariate macros.
